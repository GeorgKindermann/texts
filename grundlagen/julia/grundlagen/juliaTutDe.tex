\section{REPL}
\label{sec:repl}

Wenn man \code|julia| startet, gelangt man in den interaktiven Modus (REPL).
Die wichtigsten Tastenkombinationen und Modi sind:

\begin{description}[style=multiline,leftmargin=2cm,nolistsep]
  \item[Strg + d] Beendet die Julia-Sitzung
  \item[Strg + c] Bricht laufende Berechnungen ab
  \item[?] Aktiviert den Hilfe-Modus
  \item[;] Aktiviert den Shell-Modus
  \item[{]}] Aktiviert den Paketmanager-Modus
  \item[{]?}] Zeigt die Hilfe zum Paketmanager
  \item[Backspace] Verlässt den aktuellen Modus (zurück zu \code|julia> |)
  \item[Strg + l] Löscht den Bildschirminhalt
\end{description}

In der REPL wird nach jedem Befehl dessen Rückgabewert ausgegeben. Setzt man ein
\code|;| am Ende eines Befehls, wird die Ausgabe unterdrückt. 

Mit \code|?cos| wird direkt die Dokumentation zu \code|cos| aufgerufen. 
Über den Paketmanager-Modus lässt sich mit \code|]add Paketname| ein neues 
Paket installieren, während \code|]up| alle installierten Pakete im aktuellen 
Environment aktualisiert.

Einige grundlegende Funktionen für die interaktive Arbeit sind:

\begin{lstlisting}
versioninfo()       # Zeigt Version
varinfo()           # Listet globale Variablen auf
pwd()               # Aktuelles Verzeichnis
cd("src")           # Wechsle Verzeichnis
include("file.jl")  # Führt ein Julia-Skript aus
exit()              # Beendet die Julia-Sitzung
@edit sin(1)        # Zeigt Quelltext der Funktion
\end{lstlisting}

Ganze Skripte können außerhalb der REPL direkt über das Terminal mit 
\code|julia script.jl| ausgeführt werden.

\section{Grundtypen}
\label{sec:grundtypen}

In Julia bestimmt die Systemarchitektur die Standard-Bitbreite von Integern: Auf 32-Bit-Systemen ist \code|Int| standardmäßig \code|Int32|, auf 64-Bit-Systemen \code|Int64|.

Der Operator \code|::| dient zur Typannotation oder Typprüfung, jedoch nicht zur Typkonvertierung. Eine Typerzwingung wie \code|1::Int32| wirft auf einem 64-Bit-System einen \code|TypeError|.

\begin{lstlisting}
1             # Int (systemabhaengig)
1.0           # Float64
true          # Bool
'c'           # Char (1 Zeichen, Unicode)
"s"           # String (n Zeichen)
\end{lstlisting}

Explizite Typkonvertierungen erfolgen über Konstruktoren \code|T(x)|, die bei Informationsverlust einen \code|InexactError| werfen.

\begin{lstlisting}
Int32(1)           # Konvertierung in Int32
Int64(2.0)         # Float64 zu Int64
#Int64(1.3)        ## InexactError
floor(Int64, 1.3)  # Abrunden zu Int64
ceil(Int64, 1.3)   # Aufrunden zu Int64
round(Int64, 1.3)  # Runden zu Int64
\end{lstlisting}

Julia bietet folgende eingebene Primitivtypen:
\code|Bool|,
\code|Char|,
\code|String|,
\code|Int8| bis \code|Int128|,
\code|UInt8| bis \code|UInt128| sowie
\code|Float16|, \code|Float32| und \code|Float64|.
Die systemabhängigen Aliase \code|Int| und \code|UInt| verweisen auf die jeweilige native Bitbreite.

Die Funktion \code|string()| verkettet Argumente zu einem \code|String| (z.\,B. \code|string(1, true)| ergibt \code|"1true"|). 
Konstruktoren konvertieren zudem Zeichen und Zahlen: \code|Int64('a')| liefert den Unicode-Codepoint, \code|Char(89)| erzeugt das entsprechende Zeichen. 
\code|Bool(0)| ergibt \code|false|, \code|Bool(1)| ergibt \code|true|; andere Zahlenwerte werfen einen \code|InexactError|. 
Für die gezielte Konvertierung existieren zudem \code|convert(T, x)| (\code|convert(Int64, 1.0)|) sowie \code|parse(T, "string")| (\code|parse(Int64, "1")|) für Textparsen.

Für mathematische Spezialanwendungen existieren weitere Typen:
\begin{lstlisting}
1 // 456      # Rational (Rationale Zahl)
1 + 1im       # Complex{Int64} (Komplexe Zahl)
big"1"        # BigInt (Beliebige Praezision)
BigInt(1)     # BigInt via Konstruktor
big"1.5"      # BigFloat (Beliebige Praezision)
BigFloat(10)  # BigFloat
\end{lstlisting}

Die globale Genauigkeit von \code|BigFloat| wird mit \code|setprecision(Bits)| definiert.

Die Funktionen \code|zero(x)| und \code|one(x)| liefern die additive bzw. multiplikative Identität (Null oder Eins) des Typs von \code|x|.
Die Funktion \code|promote(args...)| gleicht alle Argumente an den kleinsten gemeinsamen Supertyp an (z.\,B. liefert \code|promote(true, 1 // 3, 2, 1.0)| ein Tuple vom Typ \code|Float64|).
Julia führt bei arithmetischen Operationen eine automatische Typaufweitung (\textit{Promotion}) durch: Bei \code|1 + 1.0| wird der Integer in ein \code|Float64| umgewandelt. \code|Bool|-Werte werden in Berechnungen (z.\,B. \code|true + true|) direkt als Integer (\code|1|) behandelt.

Typen und Hierarchien lassen sich wie folgt prüfen:
\begin{lstlisting}
typeof("abc")      # Gibt den Typ aus (String)
isa(1.0, Float64)  # true (Typfuehrung)
1.0 isa Number     # Alternative Infix-Syntax
supertype(Int64)   # Liefert den direkten Supertyp
subtypes(Real)     # Liefert direkte Subtypen
Int <: Real        # Subtyp-Pruefung (true)
\end{lstlisting}

\begin{lstlisting}
Any                      # Supertyp aller Objekte

\subsection{Tuple und NamedTuple}
\label{ssec:tuple}

Ein \emph{Tuple} speichert eine unveränderliche, geordnete Sequenz von Elementen beliebigen Typs. Die Indizierung beginnt bei 1.

\begin{lstlisting}
()              # Leeres Tuple
(1,)            # Tuple mit einem Element (Komma zwingend)
("a", 1)        # Tuple mit zwei Elementen
('a', false)::Tuple{Char, Bool}  # Typannotation
x = (1, 2, 3)
x[1]            # 1 (Element)
x[1:2]          # (1, 2) (Sub-Tuple)
x[[1, 3]]       # (1, 3) (Sub-Tuple per Array-Index)
x[begin]        # Erstes Element
x[end]          # Letztes Element
lastindex(x)    # Letzter Index von x
x[begin:2:end]  # Jedes zweite Element
#x[4]           ## BoundsError
#x[1] = 1       ## MethodError (Tuple ist immutable)
a, b = x        # Unpacking (a = 1, b = 2)
\end{lstlisting}

\emph{NamedTuples} weisen den Elementen zusätzlich Namen zu. Sie verhalten sich funktional wie Instanzen anonymer Strukturen (\hyperref[ssec:composite]{\code|struct|}).

\begin{lstlisting}
NamedTuple()  # Leeres NamedTuple
(x="a", y=1)  # NamedTuple mit zwei Elementen
x = (p=1, q=2, r=3)
x.p           # 1 (Zugriff via Name)
a = 0; b = 1
(; a, b)      # (a = 0, b = 1) (implizite Namenszuweisung)
\end{lstlisting}

\subsection{Array}
\label{ssec:array}

Die Elemente eines Arrays sind veränderbar und standardmäßig homogen, sofern nicht der Typ \code|Any| genutzt wird. In Julia ist die erste Dimension vertikal (Zeilen), die zweite horizontal (Spalten).

\begin{lstlisting}
[1]            # 1-element Vector{Int64}
[1;]           # Gleichbedeutend (vcat-Syntax)
[1;;]          # 1x1 Matrix
[1;;;]         # 1x1x1 Array
[(1, 2)]       # Vektor mit Tuple-Element
[[1, 2]]       # 1-element Vecto
[1, 2]         # Spaltenvektor (vcat)
[1; 2]         # Spaltenvektor via vcat-Funktion
[1
 2]            # Spaltenvektor via Umbruch
[[1, 2], 3]    # 2-element Vector{Any}
[[1, 2]; 3]    # 3-element Vector{Int64} flach
[[1 2] 3]      # 1x3 Matrix{Any} (hcat)
[1 2]          # 1x2 Matrix (hcat)
[1 2]::Matrix{Int64}  # Typannotation
[1;; 2]        # 1x2 Matrix
[1 2]'         # 2x1 Adjoint (shared memory)
permutedims([1 2])    # 2x1 Matrix (kopiert)
[1 3 5; 2 4 6]        # 2x3 Matrix (hvcat)
[[1 2]; [4 5]]        # 2x2 Matrix (Zeilen)
[1 3
 2 4;;;
 5 7
 6 8]                  # 2x2x2 Array (3. Dim.)
\end{lstlisting}

Ein \code|,| verkettet Elemente direkt zu einem Vektor. Ein Leerzeichen oder Zeilenumbruch erzeugt Matrizen entlang der Spalten bzw. Zeilen. Das Semikolon steuert die Dimension der Verkettung: \code|;| verkettet vertikal (1. Dimension), \code|;;| horizontal (2. Dimension), \code|;;;| nach hinten (3. Dimension) usw.

Vordefinierte Funktionen erlauben die Erzeugung uninitialisierter oder regelmäßiger Arrays:

\begin{lstlisting}
Array{Int}(undef, 2)        # Uninit. Int64-Vektor
Vector{Int}(undef, 2)       # Uninit. Int64-Vektor
Array{Int}(undef, 2, 3)     # Uninit. 2x3 Matrix
Matrix{Int}(undef, 2, 3)    # Uninit. 2x3 Matrix
Array{Int}(undef, 2, 3, 4)  # Uninit. 3D-Array
falses(3)            # BitVector mit 3x false
trues(3)             # BitVector mit 3x true
zeros(3)             # Vector{Float64} mit 0.0
ones(Int64, 2, 3)    # 2x3 Matrix{Int64} mit 1
range(0, 1, 11)      # Iterator 0 bis 1 (11 El.)
1:10                 # Iterator 1 bis 10
1:2:10               # Schritt-Iterator (1,3,..)
collect(1:10)        # Wandelt Iterator in Vector
collect((1, 2))      # unpacking Vektor aus Tuple
reshape(1:12, 3, 4)  # 3x4-Matrix aus Range
fill(7, 2, 3)        # 2x3 Matrix gefuellt mit 7
repeat([1 2], 2, 3)  # Kachelt (ergibt 2x6 Matrix)
stack([[1, 2], [3, 4]]) # Baut Spaltenmatrix
stack([[1,2], [3,4]], dims=1) # Horizontal
x = [1, 2]           # 2-element Vector
resize!(x, 5)        # In-place Groessenaenderung
tuple([1,2,3])       # 1-Element Tuple mit dem Vektor
Tuple([1, 2, 3])     # Wandelt Vector in Tuple
\end{lstlisting}

\emph{Comprehensions} generieren Arrays mittels Schleifen und optionalen Bedingungen:

\begin{lstlisting}
[x * y for x in 1:2, y in 1:3]    # 2x3 Matrix
[x * y for x in 1:2 for y in 1:3] # 6-el. Vector
Float64[x^2 for x in -2:2]        # Typisierter Vector
[x * y for x=1:3 for y=1:x if x+y == 4]  # Mit if
\end{lstlisting}

Wird bei der Index-Generierung eine Dimension mit nur einem Element deklariert (z.\,B. \code|1|), bricht Julia diese Dimension ab. Um sie als Dimension der Länge 1 zu erhalten, nutzt man eine Range (z.\,B. \code|1:1|).

\begin{lstlisting}
[x * y for x in 1:2, y in 1]    # 2-element Vector
[x * y for x in 1:2, y in 1:1]  # 2×1 Matrix
\end{lstlisting}

Wichtige Funktionen zur Array-Analyse und Reduktion:
\begin{lstlisting}
A = rand(2, 1, 3)    # 2x1x3 Matrix{Float64, 3}
ndims(A)             # Anzahl Dimensionen (3)
eltype(A)            # Elementtyp (Float64)
length(A)            # Gesamte Elementanzahl (6)
size(A)              # Dimensionslaengen ((2,1,3))
axes(A)              # Tuple mit Ranges der Dimensionen
eachindex(A)         # Linearer Index-Iterator (1:6)
CartesianIndices(A)  # Lazy Mehrdim. Index-Iterator
LinearIndices(A)     # Lazy linear Iterator von A
vec(A)               # Abflachen (shared memory)
dropdims(A, dims=2)  # Entfernt 2. Dim die 1 lang ist
sum(A, dims=3)       # Summe laengs 3. Dimension
sum(A, dims=(1,2))   # 1x1x3 Array{Float64, 3}
sum(A, dims=[1,2])   # 1x1x3 Array{Float64, 3}
count(>(0.5), A)     # Zaehlt Elemente > 0.5
any(>(0.5), A)       # true, wenn ein Element > 0.5
all(>(0.5), A)       # Alle Werte > 0.5: true/false
\end{lstlisting}

Der Zugriff auf Array-Elemente erfolgt primär wie bei \hyperref[ssec:tuple]{Tuples}. Mehrdimensionale Arrays erlauben zudem einen rein linearen Zugriff (als wäre es ein Vektor). Weitere Indizierungsoptionen:

\begin{lstlisting}
A = reshape(collect(1:24), (2, 3, :)) # 2x3x4 Array
A[[true, false], [3, 1], 1]   # Logischer Index
A[1, :, 1:2]         # : waehlt ganze Dimension
A[1:1, 1, :]         # 1x4 Matrix
A[1, 1, :]           # 4-element Vector
A[1, 1, :, [true]]   # 4x1 Matrix
A[1, 1, :, [false]]  # 4x0 Matrix
A[[1, 7, 3]]         # Linearer Vektor-Index
A[[1 7 3]]           # Gleiche Daten aber: 1x3 Matrix
A[[1 7 3; 2 5 7]]    # Output-Form folgt Index-Form
A[1, 1, 2:end-1]     # end ist der letzte Index
view(A, [1, 9])  # SubVektor von A, Zeigt auf Daten von A
view(A, 1:2, 2:3, 4) # View (shared memory)
\end{lstlisting}

Modifikation von Array-Daten:

\begin{lstlisting}
A = reshape(Vector(1:12), (3, 4))
A[2, 1] = 3          # In-place Einzelwert
#A[:, 2:3] = 3      ## Error size mismatch
A[:, 2:3] .= 3       # In-place Broadcasting
A[:, 2:3] .= [1 2]  # Automatisch wiederholt
A[:, 2:3] = repeat([1 2], 3)  # das gleiche
x = A[:, 2:3]        # Erstellt unabhaengige Kopie
y = view(A, :, 2:3)  # View auf Originaldaten
y .= 5               # Modifiziert A implizit
\end{lstlisting}

Arrays verhalten sich wie \emph{Referenzen}. Die Zuweisung \code|x = A| kopiert nicht die Daten. Flache Kopien erzeugt \code|copy|, rekursive Tiefenkopien liefert \code|deepcopy|.

\begin{lstlisting}
A = [[2, 1], 1]  # Vektor mit Sub-Vektor
x = A            # Referenz-Zuweisung
y = copy(A)      # Kopiert nur aeussere Struktur
z = deepcopy(A)  # Kopiert alle Daten rekursiv
A[1][1] = 0      # Modifiziert A, x und y
A[2] = 3.0       # y und z bleiben unberuehrt
x                # Identisch mit neuem A
y                # Nur Veränderung von A[1][1]
z                # Inhalt wie ursprüngliches A
\end{lstlisting}

Skalare Zahlen lassen sich formal wie 0-dimensionale Arrays oder Ein-Element-Vektoren indizieren:

\begin{lstlisting}
x = 10
x[]       # 10 (0-D Zugriff)
x[1]      # 10
x[1, 1]   # 10 (Folge-Indizes von 1 ignoriert)
only(x)   # 10
size(x)   # () (Leeres Tuple fuer Skalare)
y = [10]  # 1-element Vector
y[]       # 10 (Geht nur bei genau 1 Element)
size(y)   # (1,)
\end{lstlisting}

Beliebige Objekte können mittels \code|Ref| in einen expliziten, veränderbaren 0-dimensionalen Container gekapselt werden:

\begin{lstlisting}
x = Ref("a")  # Typ: Base.RefValue{String}
x[]           # "a" (Dereferenzierung)
#x[] = 2     ## Error Cannot `convert`
x[] = "b"     # OK (Zuweisung gleichen Typs)
\end{lstlisting}

\subsection{Composite -- Struct}
\label{ssec:composite}

Zusammengesetzte Typen (Composite Types) sind Sammlungen benannter Felder 
und werden mit \code|struct| definiert. Standardmäßig sind sie unveränderlich (immutable).

\begin{lstlisting}
struct X
  a::Int
  b               # Typ Any
end
x = X(0.5, 1.5)   # InexactError: Konvertierung schlägt fehl
x = X(0, 1.5)     # OK
x.a               # Zugriff auf Feld a
x.a = 1           # Error: immutable struct

mutable struct Y  # Veränderbare Struct
  a::Int
  b
  const c         # Einzelnes Feld nicht veränderbar
end
y = Y(0, 1, 2)    # OK
y.a = 1           # OK
y.a = 1.3         # InexactError: Konvertierung schlägt fehl
y.b = 1.3         # OK
y.c = 3           # Error: const field
y.d = 5           # Error: no field d

fieldnames(Y)     # (:a, :b, :c)
fieldtypes(Y)     # (Int64, Any, Any)
fieldtype(Y, 1)   # Int64; Über Position
fieldtype(Y, :a)  # Int64; Über Name
\end{lstlisting}

Felder ohne Typangabe erhalten den Typ \code|Any|. 
\hyperref[ssec:tuple]{Named Tuples} verhalten sich wie anonyme, 
unveränderliche Structs.

Unveränderliche Typen (\code|struct|) werden von 
Julia meist direkt auf dem Stack oder inline in Arrays allokiert. Das 
vermeidet Heap-Allokationen und entlastet den Garbage Collector. 
Veränderliche Typen (\code|mutable struct|) erzwingen hingegen meist 
Heap-Allokationen und Speicherzugriffe über Pointer, was in engen Schleifen 
zu Performance-Einbußen führen kann.

\subsection{Union}
\label{ssec:union}

Eine \code|Union| fasst mehrere Typen zu einem gemeinsamen, abstrakten Typ 
zusammen. Ein Wert entspricht dem Union-Typ, wenn er Instanz eines der 
enthaltenen Typen ist.

\begin{lstlisting}
IntOrStr = Union{Int,String}     # Int oder String
1 :: IntOrStr                    # OK
"Hello!" :: IntOrStr             # OK
1.0 :: IntOrStr                  # TypeError
\end{lstlisting}

\subsection{Abstract Type}
\label{ssec:AbstractType}

Abstrakte Typen dienen als Strukturierungselemente, um eine gemeinsame 
Typhierarchie für eigene Typen zu definieren. Sie können selbst keine 
Instanzen (Objekte) erzeugen, sondern nur als Oberflächen für Subtypen fungieren.

\begin{lstlisting}
abstract type A end
abstract type B <: A end  # B ist Subtyp von A
struct X <: A a end       # X ist Subtyp von A
struct Y <: B; b; end     # Y ist Subtyp von B
subtypes(A)               # Any[B, X]
subtypes(B)               # Any[Y]
supertype(Y)              # B
Y <: A                    # true
Y <: X                    # false
\end{lstlisting}

\subsection{Dictionaries}
\label{ssec:dictionary}

Dictionaries (\code|Dict|) speichern Key-Value-Paare, bei denen eindeutige 
Schlüssel auf bestimmte Werte abgebildet werden.

\begin{lstlisting}
D = Dict{Char, Int64}()         # Leeres Dict Char => Int
D = Dict('a'=>2, 'b'=>3)        # Dict mit 2 Einträgen
D = Dict([('a', 2), ('b', 3)])  # Alternative Erzeugung
D['a']                          # 2
#D['c']                        ## KeyError: key not found
D['c'] = 3                      # Element einfügen
haskey(D, 'b')                  # true
keys(D)                         # Iterierbare Schlüssel
values(D)                       # Iterierbare Werte
pairs(D)                        # Iterierbare Paare
delete!(D, 'b')                 # Löscht Eintrag b
pop!(D, 'a')                    # Holt Wert von a, löscht a
get(D, 'd', 0)                  # Wert von d, sonst 0
\end{lstlisting}

\subsection{Set}
\label{ssec:set}

Ein \code|Set| ist eine ungeordnete Sammlung einzigartiger (unique) Werte. 
Jedes Element kann nur einmal vorkommen.

\begin{lstlisting}
S = Set([1, 4, 7])  # Erzeugt Set(1, 4, 7)
push!(S, 2)         # Fügt 2 ein
push!(S, 4)         # Keine Änderung, da 4 existiert
union(S, 2:3)       # Neues Set mit Werten aus S und 2:3
intersect(S, 1:3)   # Neues Set mit Werten in S und 1:3
\end{lstlisting}

\section{String}
\label{sec:string}

Strings sind in UTF-8 codierte Sequenzen von Zeichen (\code|Char|). Die 
Zeichenkodierung nutzt eine variable Länge von 1 bis 4 Byte. Der Indexzugriff 
erfolgt per Byte-Index, weshalb ungültige Byte-Adressen Fehler auslösen.

\begin{lstlisting}
s = "Mehr \"Licht\"!"    # " per \ escapen
s = """Mehr "Licht"!"""  # Alternativ mit Dreifach-Anfuehrungsz.
s = "Mehr \
     \"Licht\"!"         # Zeilenumbruch im Code wird ignoriert
s = "AÄ" * "oö"          # Strings verketten
length(s)                # 4 (Anzahl Zeichen)
ncodeunits(s)            # 6 (Anzahl Bytes)
collect("abü")           # Array von Char: ['a', 'b', 'ü']
collect(eachindex(s))    # Byte-Indizes: [1, 2, 4, 5]
#s[3]                  ## StringIndexError (Byte 3 ist ungültig)
for c in s print(c) end  # Iteration ueber jedes Zeichen
#SubString(s, 1, 3)     ## StringIndexError
SubString(s, 1, nextind(s, 0, 3))  # "AÄo"
nextind(s, 2)            # 4 (Naechster gueltiger Index nach 2)
prevind(s, 4)            # 2 (Vorheriger gueltiger Index vor 4)
repeat("Ja ", 3)         # "Ja Ja Ja "
"Ja " ^ 3                # Alternativ per Potenz-Operator
string("x = ", 2.7)      # String via print-Logik erzeugen
repr(123.3)              # String-Repraesentation: "123.3"
s = "xylophone"
chop(s)                  # Entfernt letztes Zeichen: "xylophon"
occursin("o", s)         # true (Sub-String enthalten?)
findfirst('o', s)        # 4
findlast('o', s)         # 7
findnext('o', s, 5)      # 7
findprev('o', s, 5)      # 4
s = "\n\t\$"             # Umbruch, Tabulator, Dollarzeichen
x = 123
s = "$x + 3 = $(x+3)"    # Interpolation: "123 + 3 = 126"
print(raw"D:\path \\\"") # Gibt Rohdaten aus: D:\path \"
\end{lstlisting}

\code|SubString| erzeugt keine Kopie, sondern referenziert einen Ausschnitt des 
Originals. \code|String| und \code|SubString| sind Subtypen von \code|AbstractString|, welcher in eigenen 
Funktionen als Argumenttyp genutzt werden sollte.

Für reguläre Ausdrücke nutzt Julia PCRE2 (Perl Compatible Regular Expressions) via \code|r"..."|. Für Ersetzungen 
wird ein Substitutions-String via \code|s"..."| deklariert.

\begin{lstlisting}
re = r"[ÄÖÜ]."       # Ä, Ö oder Ü gefolgt von beliebigem Zeichen
occursin(re, "ABC")  # false
s = "ÄÖÜX"
m = match(re, s)     # RegexMatch("ÄÖ") (Erster Treffer)
m.offset             # 1 (Start-Byte)
m.match              # "ÄÖ"
length(m.match)      # 2
ncodeunits(m.match)  # 4
match(re, s, m.offset + 1)                    # "ÖÜ"
match(re, s, m.offset + ncodeunits(m.match))  # "ÜX"
collect(eachmatch(re, s))                     # ["ÄÖ", "ÜX"]
collect(eachmatch(re, s, overlap=true)) # ["ÄÖ", "ÖÜ", "ÜX"]
replace("ABCBA", r"([AC])" => s"\1X", count=2)# "AXBCXBA"
\end{lstlisting}

\section{Programmierung}
\label{sec:programmierung}

Wertzuweisungen an Variablen erfolgen mit dem Operator \code|=|.

\begin{lstlisting}
x = "A"  # Zuweisung eines Strings
x = 1    # Dynamische Typaenderung erlaubt
\end{lstlisting}

Verbundene Ausdrücke (Compound Expressions) fassen mehrere Anweisungen 
zusammen. Sie werden mit \code|begin ... end| oder per \code|;| blockiert.

\begin{lstlisting}
z = begin
  x = 1   
  y = 2;  # Semikolon optional
  x + y   # Letzter Wert wird zurueckgegeben
end       # x = 1, y = 2, z = 3
z = (x = 1; y = 2; x + y)          # Alternative in einer Zeile
z = begin x = 1; y = 2; x + y end  # Alternative mit begin
\end{lstlisting}

Bedingte Verzweigungen (\code|if|, \code|elseif|, \code|else|) erfordern 
strikt Werte vom Typ \code|Bool|.

\begin{lstlisting}
if false
  z = 1
elseif 1 == 2
  z = 2
else
  a = 3
end         # a = 3, z bleibt undefiniert
1==2 ? "A" : "B"  # "B" (Ternaerer Operator)
\end{lstlisting}

Schleifen (\code|while| und \code|for|):

\begin{lstlisting}
i = 1
while true
  global i += 1       # global bei REPL nicht nötig
  if i > 10 break end # Vorzeitiger Abbruch
end
for k in 1:10         # Alternativ: k = 1:10
  if 3 < k < 6
    continue          # Springt zur naechsten Iteration
  end
  println(k)
end
# Schleifenvariablen sind lokal im Schleifen-Scope
\end{lstlisting}

Funktionen geben den Wert des letzten Ausdrucks oder ein explizites 
\code|return| zurück. Funktionen, deren Name auf \code|!| endet, verändern 
konventionsgemäß ihre Argumente im Speicher (in-place).

\begin{lstlisting}
f(x, y = 10) = x + y       # Funktion f mit Argumenten x
   # und y wobei y einen Defaultwert hat
function f(x, y = 10)      # Langform
  x + y
end
f(3, 2)                    # 5
f(3)                       # 13 (nutzt Default-Wert)
(function (x) x^2 end)(3)  # Anonyme Funktion samt Aufruf
(x -> x^2)(3)              # Alternative
(() -> 0)()                # Anonym ohne Argumente: 0
((x, y) -> x/y)(4, 2)      # Anonym mit zwei Argumenten: 2.0
h(a, x...) = a + sum(x)/length(x)  # Varargs (x ist Tuple)
h(1, 2, 3)                 # 3.5
x_tup = (2, 3)
#f(x_tup)                 ## MethodError
f(x_tup...)                # 5 (Tuple Unpacking)
s(x; a=1, b=1) = x * a / b # Keyword-Argumente nach Semikolon
s(3, b=2)                  # Aufruf mit Keyword-Argument: 1.5
q(f::Function, x) = 2 * f(x)   # Funktion als Argument
q(x -> 2x, 10)                 # 40 (Implizite Multiplikation)
q(10) do x                 # Alternative via do-Block
  2 * x
end
m = reshape(1:12, 3, 4)
m.^2                        # Elementweise Quadrierung (.^)
map(x -> x^2, m)            # Alternative via map
2 in [1, 2, 3]              # true; Enthält 2
filter(x -> x % 2 == 0, 6:9)   # [6, 8]; Elemente wo true
findall(x -> x % 2 == 0, 6:9)  # [1, 3]; Indices wo true
indexin(3:5, 2:4)              # [2, 3, nothing]; Trefferindex
findall(==(1), (-2:2).^2)      # [2, 4]; Indices wo Wert 1
==(1)                          # Funktion Test == 1
findfirst(==(1), (-2:2).^2)    # 2
findlast(==(1), (-2:2).^2)     # 4
\end{lstlisting}

Optionale Funktionsargumente werden von links nach rechts evaluiert.

\begin{lstlisting}
y = 10
f1(x=y)        = x; f1()  # 10
f2(x=y, y=1)   = x; f2()  # 10
f3(y=1, x=y)   = x; f3()  # 1
f4(; x=y)      = x; f4()  # 10
f5(; x=y, y=1) = x; f5()  # 10
f6(; y=1, x=y) = x; f6()  # 1
\end{lstlisting}

Besitzt eine Funktion verschiedene Implementierungen basierend auf den 
Argumenttypen, nennt man dies \emph{Multiple Dispatch}. Dafür werden 
ausschließlich Positionsargumente ausgewertet.

\begin{lstlisting}
g(x, y) = 0              # Fallback fuer alle Typen
g(x::Int, y::Int) = 1    # Spezifisch fuer zwei Ints
g(x::Int, y::Bool) = 2   # Spezifisch fuer Int und Bool
g(1.0, 1)                # 0
g(1, 1)                  # 1
g(1, true)               # 2
g(x::Int, y::Int=1) = 3  # Definiert g(x::Int, y::Int) neu!
g(1)                     # 3 (Nutzt den Default-Wert)
g(1, 1)                  # 3 (Ueberschreibt die alte Methode)
methods(g)               # Zeigt alle verfuegbaren Methoden
t(; x::Int = 2) = 4      # Definition mit Keyword-Argument
t(x=3)                   # 4
t(; x::Bool = true) = 5  # Ueberschreibt vorherige Funktion!
# (Kein Multiple Dispatch fuer Keyword-Argumente)
#t(x=3)                 ## TypeError (Erwartet jetzt Bool)
t()                      # 5
t(x=false)               # 5
\end{lstlisting}

\section{Gültigkeitsbereich (Scope) von Variablen}
\label{sec:scopeVonVariable}

Der Gültigkeitsbereich (Scope) bestimmt den Codebereich, in dem eine Variable 
sichtbar ist. Julia nutzt \emph{lexical scoping}: Scopes erben Variablen aus 
ihrem übergeordneten Definitionskontext, nicht aus dem Aufrufkontext.

Einen eigenen lokalen Scope besitzen: \code|module|, \code|struct|, \code|for|, 
\code|while|, \code|try/catch|, \code|macro|, \code|function|, \code|do|-Blöcke, 
\code|let|-Blöcke, \code|comprehensions| und \code|generators|. Kein eigener Scope 
wird durch \code|begin|- und \code|if|-Blöcke geöffnet.

Variablen-Deklarationen:
\begin{description}[style=multiline,leftmargin=1.3cm,nolistsep]
  \item[global] Deklariert oder nutzt eine Variable im globalen Scope.
  \item[local] Erzwingt eine neue Variable im aktuellen lokalen Scope.
  \item[const] Bindet globale Variablen fest an ihren Wert (Compiler-Optimierung).
\end{description}

\begin{lstlisting}
f() = global t = 1  # Definiert globale Variable t bei Aufruf
#t                 ## Error: t noch nicht definiert
f()                 # Initialisiert t global
t                   # 1

function f1(n)
  x = 0
  for i = 1:n
    x = i           # Nutzt die äussere lokale Variable x
  end
  x
end
f1(10)              # 10

function f2(n)
  x = 0
  for i = 1:n
    local x         # Neue lokale Variable im Schleifen-Scope
    x = i
  end
  x
end
f2(10)              # 0

function f3(n)
  for i = 1:n
    h = i
  end
  h                 # Error: h ist ausserhalb nicht definiert
end
#f3(10)

function f4(n)
  local h
  for i = 1:n
    h = i           # Nutzt deklariertes äusseres h
  end
  h
end
f4(10)              # 10

const x = 2
#x = 3             ## Error: Wert von Konstante geaendert
#x = 2.0           ## Error: Ungueltige Typaenderung fuer const
y::Int = 1          # Globale Variable mit Typisierung
#y = 2.5           ## InexactError: Muss Int bleiben
\end{lstlisting}

Globale Konstanten (\code|const|) können die Performance verbessern, da 
der Compiler ihren Typ statisch ableiten kann.

Schleifen und Comprehensions 
erzeugen ihre Schleifenvariablen bei jedem Iterationsschritt neu (Closure-Sicherheit).

\begin{lstlisting}
Fs = Array{Any}(undef, 2)
for i in 1:2
  Fs[i] = () -> i   # i wird für jede Instanz neu gebunden
end
Fs[1](), Fs[2]()    # (1, 2)
\end{lstlisting}

Top-Level-Schleifen (\code|for|, \code|while|) sowie \code|try|, und \code|struct| besitzen einen \emph{soft local scope}. 
In der REPL (interaktiv) überschreiben sie bestehende globale Variablen direkt.

\begin{lstlisting}
x = 5
for i in 1:10
  x = i             # Ueberschreibt globales x in der REPL
end
x                   # 10
\end{lstlisting}

In Skripten (nicht-interaktiv) führt dies ohne explizites Keyword zu 
Mehrdeutigkeiten, einer Warnung und dem standardmäßigen Anlegen einer lokalen Variable:

\begin{lstlisting}
# Ausführung als Skript:
julia -e "x=5; for i in 1:10 x = i end; println(x)"
# Warning: Assignment to `x` in soft scope is ambiguous...
# Ausgabe: 5
\end{lstlisting}

Eindeutigkeit wird durch \code|local|, \code|global| oder \code|let|-Blöcke 
erzwungen:

\begin{lstlisting}
x = 5
for i in 1:10
  local x = i
end
x                   # 5 (Globales x bleibt unberuehrt)

x = 5
for i in 1:10
  global x = i
end
x                   # 10 (Globales x explizit ueberschrieben)

let x = 5
  for i in 1:10
      x = i
  end
  x
end                 # 10 (Lokales x im let-Scope veraendert)
\end{lstlisting}

\section{Modul}
\label{sec:modul}

Module kapseln Programmteile in eigenen globalen Namensräumen (Namespaces) 
ab. Der Standard-Namensraum der REPL lautet \code|Main|.

\begin{lstlisting}

export x, y   # Deklariert oeffentliche Schnittstelle
x = 1
y = 2
z = 3         # Internes Feld (nicht exportiert)
end
varinfo(M)    # Zeigt exportierte Symbole (x, y) in M an
#x           ## Error: Nicht im aktuellen Scope vorhanden
M.z           # Qualifizierter Direktzugriff ist immer moeglich
using .M: x   # Importiert ausschliesslich x aus M
x             # 1
#y           y# Error: y wurde noch nicht importiert
using .M      # Importiert alle exportierten Variablen (x, y)
y             # 2
#z           ## Error: z ist nicht exportiert
import .M.z   # Importiert das interne z explizit
using .M: z   # Alternative für gezielten Import
z             # 3
using Random  # Lädt externe Standard- oder Drittanbieter-Pakete
\end{lstlisting}

Das lokale Überschreiben (Rebinding) von automatisch aus 
Base verfügbaren Namen ist erlaubt. Das Objekt verliert 
dadurch jedoch seine ursprüngliche Funktion.

\begin{lstlisting}
sin(0)      # 0.0 (Automatisch aus Base verfuegbar)
sin = 1     # Erlaubt: Ueberschreibt den Namen lokal
sin         # 1
#sin(0)    ## MethodError: Int64 ist nicht aufrufbar
Base.sin(0) # 0.0 (Expliziter Base-Aufruf weiterhin möglich)
\end{lstlisting}

\section{Lesen und Schreiben von Dateien}
\label{sec:fileIO}

Das Öffnen von Dateien erfolgt über \code|open|. Die \code|do|-Block-Syntax
garantiert das automatische Schließen. Für performantes Zeilenlesen wird
\code|eachline| bevorzugt, da es die Datei streamt.

\begin{lstlisting}
f = tempname()                   # Temporärer Pfad
open(f, "w") do io               # Öffnen zum Schreiben
  write(io, "Zeile 1\nZeile 2\n")# Schreiben
end                              # Schließen
open(f, "r") do io               # Öffnen zum Lesen
  for line in eachline(io)       # Zeilenweise streamen
    println(line)                # Ausgeben
  end
end                              # Schließen
lines = readlines(f)             # Alles als Array laden
rm(f)                            # Datei löschen
\end{lstlisting}

Das Standardbibliotheksmodul \code|DelimitedFiles| importiert und exportiert
Matrizen. Trennzeichen am Ende (besonders Leerzeichen) werden nicht ignoriert.

\begin{lstlisting}
using DelimitedFiles
M = [1 3 5; 2 4 6]               # Matrix
f = tempname()                   # Temporärer Pfad
writedlm(f, M)                   # Datei schreiben
A = readdlm(f, '\t', Int, '\n')  # Datei einlesen
A == M                           # true
rm(f)                            # Datei löschen
\end{lstlisting}

\section{Makros}
\label{sec:macros}

Makros verändern Code vor der Ausführung auf Syntax-Ebene.
Eigene Definitionen nutzen das Schlüsselwort \code|macro|. 
Der Doppelpunkt \code|:| zitiert Code (Expression), 
\code|\$| interpoliert Werte hinein:

\begin{lstlisting}
macro doppel(x)
    return :($x * 2) # Gibt zitierten Code zurueck
end

@doppel(5)           # Ergibt 10
\end{lstlisting}

Nützliche Standardmakros für Prüfungen und Benchmarks:
\begin{lstlisting}
@assert 1 == 1 "ERROR"            # OK
#@assert 1 == 2 "ERROR"          ## AssertionError

using Test                        # Für Unit-Tests
#@test 1 == 2                    ## Fail (zeigt Details)
@test_throws DomainError sqrt(-1) # Prüft auf Error
\end{lstlisting}

\begin{lstlisting}
# [...] erzeugt echtes Array im Speicher (fuer Demo)
f() = sum([x for x in 1:10^6])

@time f()                    # Zeit und Speicher
@timed f()                   # Liefert Wert, Zeit, Bytes
@elapsed f()                 # Liefert nur Zeit (Float64)
@allocated f()               # Liefert nur Speicher (Bytes)
# Schutz vor Compiler-Optimierung (Code Elimination)
@time Base.donotdelete(f())  
\end{lstlisting}

Das Paket \code|BenchmarkTools.jl| bietet präzisere
Messungen durch automatische Wiederholungen. Globale 
Variablen müssen mit \code{\mbox{\$}} interpoliert werden, um

\section{Visualisierung -- Plot}
\label{sec:plot}

Das Metapaket \code|Plots.jl| bietet eine einheitliche 
Schnittstelle. Die eigentliche Grafik wird von austauschbaren 
Backends generiert. Standard ist \code|gr()|.

\begin{lstlisting}
#]add Plots
using Plots, Random
Random.seed!(1)
x, y = 1:100, randn(100)

p1 = plot(x, y)           # Linien
p2 = scatter(x, y)        # Punkte
p3 = histogram(y)         # Histogramm
p4 = bar(y)               # Balkendiagramm

# Kombinieren und speichern
p0 = plot(p1, p2, p3, p4, layout=(2,2), legend=false)
savefig(p0, "pic.pdf")

#]add UnicodePlots
using UnicodePlots
unicodeplots()      # Rendert Plots als Text in der REPL
plot(x, y)
gr()                # Wechselt zu GR zurück
plot(x, y)
\end{lstlisting}
